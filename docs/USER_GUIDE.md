## 模型配置来源

OpenAI Responses 的完整显式配置由以下三项组成，去除首尾空白后均须非空：

| 配置 | 来源 |
| --- | --- |
| 端点 | `BOSS_HARNESS_OPENAI_BASE_URL` |
| 凭据 | `BOSS_HARNESS_OPENAI_API_KEY` |
| 模型 | 命令行 `--model`，其次为 `BOSS_HARNESS_MODEL` |

三项齐备时不访问 Codex 配置文件，Python 3.10 也可使用这一路线；可选推理强度只取 `BOSS_HARNESS_EFFORT`，未指定则由模型服务决定，不再继承文件中的值。没有 `BOSS_HARNESS_OPENAI_MODEL` 别名。

缺少任一项时才读取 `BOSS_HARNESS_CODEX_CONFIG`、`CODEX_HOME/config.toml` 或默认 `~/.codex/config.toml`，按此顺序选择文件，显式字段仍优先。读取 TOML 需要 Python 3.11+；已有文件不可读或语法损坏时明确报错，不退到其他 provider。文件不存在或缺少可用 profile 时继续检查端点与凭据，缺项会报错；未提供模型且没有可用文件模型时保留既有 `DEFAULT_MODEL`。

当前文件适配要求文件自身同时提供 `model`、`model_provider` 及该 provider 的 `base_url` 才形成可用 profile；认证仅识别 `experimental_bearer_token`，尚未适配 Codex 的 `env_key`、OAuth 或任意 `wire_api`。配置解析只读本地文件，不探测真实服务。

## 单次模型请求期限

OpenAI Responses 与 Anthropic Messages 的单次传输默认最多运行 600 秒，可用 `BOSS_HARNESS_MODEL_REQUEST_TIMEOUT_SECONDS` 设置为 1–3600 的整数秒。该 wall-clock 总时限覆盖连接建立和流式响应；SDK 原有的 30 秒连接/读取空闲时限仍然生效，周期性 SSE 心跳不会延长总时限。

超时不会标记为用户取消，也不进入上下文溢出恢复。后台清理在期限内确认完成时，它作为可重试传输错误结束；若清理仍未完成，内核停止自动重试并保留该传输的资源额度。OpenAI 仅在尚无可见输出且清理已确认时遵循既有重试策略，每次 attempt 各自重新计时；Anthropic 不新增自动重试。这不是跨重试或 Agent 自动恢复的共享总预算。

每个内核进程最多保留 8 个模型传输，业务回合、摘要与连接检查共同使用；未完成后台清理的传输也占用额度，满额时新请求在发出前失败。流事件队列最多保留 64 项、估算共 4 MiB，单事件最多 2 MiB。该预算针对 SDK 已解码对象，不能限制 SDK 解码单帧时的临时内存或整个进程 RSS。

## 技能与队列

把运行时技能放在工作区 `.boss-harness/skills/<id>/SKILL.md`（旧 `.boss-cli/skills` 仍兼容读取），可用 frontmatter 的 `name` 与 `description` 提供菜单名称和说明。在输入区选择技能后，它会随一次直接发送或「排到后续回合」的队列消息进入该回合的提示上下文；技能不会执行目录脚本，也不会扩大工具清单或审批范围。目录最多发现 100 个普通技能文件，每个文件最多 64 KiB；每次最多选择 10 项。转向当前回合的消息不使用技能，已选技能时会提示清除或改为后续回合。

任务运行时，可将新消息转向当前回合，或排到当前回合结束后；停止任务是独立操作。队列状态会持久化，尚未投递的项目可以撤回。启动失败且确认输入尚未写入会话的后续回合项可直接「重新排队」：沿用原输入与技能创建新队列消息，并撤回旧项；其余失败、结果不确定或结算异常时，队列会暂停并要求先核对；不会自动重放工具、审批或招聘平台操作。相同 `clientUserMessageId` 会关联原请求，输入已接受不表示回合已成功。仍在排队的消息可在投递前经 `queue/update` 编辑正文：只接受 `queued` 项，保留技能、自动压缩覆盖与请求编号，正文仍限 1–100000 字符并受待处理队列字节上限约束；桌面编辑截断项时会先读取完整正文。会话读取与 `queue/list` 只返回待处理项及最近 50 个已终结项（单次最多 200 项），正文预览最多 600 字符并标注截断；重新排队经 `queue/get` 读取该项完整正文与技能，不会复用预览。

## 自动压缩默认策略

内核默认启用自动压缩：输入预算使用达到 80% 时生成摘要，并尽量保留最近 20000 token。桌面「设置 → 上下文」可查看并修改这三项默认值；内核侧对应 `config/autoCompaction/set`（能力 `autoCompactionConfig`），只接受 `enabled`、`triggerPercent`（1–100）与 `keepRecentTokens`（1–1000000）。保存后立即在当前进程生效，并原子写入内核状态目录下的 `config.json`；重启后仍生效，其他顶层配置键保持不变。摘要使用的 provider、model、effort 不在此界面修改，仍由启动配置决定。

策略来源经 `config/read` 的 `autoCompactionSource` 如实返回：`environment` 表示由 `BOSS_HARNESS_COMPACTION` 管理，`stored` 表示来自 `config.json`，`default` 表示内置默认，`explicit` 表示调用方在构造内核时显式指定。环境变量优先于持久配置；此时设置页只读，直接调用 `config/autoCompaction/set` 会以 `AUTO_COMPACTION_ENV_MANAGED` 拒绝，不会静默覆盖环境变量；显式构造的内核以 `AUTO_COMPACTION_EXPLICIT` 拒绝写入。配置文件缺失或字段非法时按内置默认读取；文件存在但不可读或不是 JSON 对象时，保存会明确失败而不是覆盖原文件。单回合覆盖的语义不变：它优先于默认值，发送一次后消耗，不写入会话或 `config.json`。

## 运行状态

按 `⌘⇧K` 或选择侧栏「运行状态」打开只读面板。每次打开会并行读取当前进程的配置、运行资源、待审批、工具与模型目录；存在当前会话时还会读取该会话的待处理队列。面板不跨会话合并数据，切换会话后重新打开即按新会话读取。

概览展示 Provider、模型、协议、上下文窗口与输出上限、并发与保留回合、运行或收尾中的 owner、容量等待、审批与工具/模型数量以及自动压缩策略；「回合」列出 owner 与等待者明细，「审批」列出待审批调用与到期提示，「工具与模型」列出 allowlist 属性与本机模型线路。单个来源读取失败只影响对应分区并显示真实原因，其余分区继续展示；内核断连时清空数据并提示未连接。

当前版本不接入 MCP，也不提供成本、缓存命中率、沙箱或死循环指标；面板不会用示例值填充未知字段。模型条目的 `available` 仅表示本机线路配置可用，不代表网络连通性或招聘平台验证。

## 上游 CLI 设置

业务可执行文件依次从 `BOSS_CLI_BIN`、并排的 `boss-agent-cli/.venv/bin/boss`、PATH 查找。`BOSS_CLI_DATA_DIR` 管理上游登录和平台状态；`BOSS_HARNESS_DIR` 管理本项目会话（旧 `BOSS_CLI_HARNESS_DIR` 仍兼容），两者应分别配置。

可在启动 Harness 或桌面应用前设置 `BOSS_HARNESS_BROWSER_SOURCE` 为 `auto`、`existing-browser` 或 `stored-cookie`。未设置时继承上游配置；显式设置需要上游支持 `--browser-source`，不支持时会明确失败，不会静默重试。该选项不会读取或改写共享上游配置，也不替代单独的请求和认证边界检查。

## 明确条件搜索

在模型会话中可以要求“上海 Python、20–50K、3–5 年、本科，先看第一页”，模型通过 `boss_search` 传递结构化条件：

```json
{"keyword":"Python","city":"上海","salary":"20-50K","experience":"3-5年","education":"本科","page":1}
```

随后查看第二页时保持全部条件，只把 `page` 改为 `2`。工具不会自动拉取下一页，也不会自动放宽条件或逐个补取详情。平台返回 `has_more=null` 或没有分页信息时，是否还有后续结果仍未知；本页数量不能当作全量总数。

城市及岗位标签受当前适配契约的枚举约束，可通过 `tool/list` 查看。未知城市、标签、额外字段或非正整数页码在执行前被拒绝；旧 CLI 不支持新选项时保留明确错误，不去掉条件重查。平台标签与上游本地预筛不构成严格资格证明：经验、学历或薪资字段未知时须注明未知，再结合职位原始要求分析。

经验、学历也接受非空、无重复的枚举数组，例如“3–5 年或 5–10 年，本科或硕士”：

```json
{"keyword":"Python","city":"上海","experience":["3-5年","5-10年"],"education":["本科","硕士"],"page":1}
```

数组表示同一维度的任一标签，两个维度同时提交到一次指定页查询；不拆成组合搜索。传给业务 CLI 时按固定枚举顺序生成单个逗号参数，原始数组留在会话记录中。空数组、重复/未知标签、混合类型及逗号字符串均拒绝；省略字段才表示不设条件。下一页重复全部条件，仅改页码。城市、薪资仍只接受单标签。

多标签依赖平台筛选；当前业务上游对逗号经验/学历不执行单标签顺序粗筛。离线验证只能证明参数传递，不能证明平台严格返回集合内结果；须核对返回字段并标注未知或不匹配项。一次调用至多查询指定逻辑列表页，不补详情；缓存命中可能不发列表请求。网络尝试、认证及缓存维护仍由业务 CLI 决定，不能按工具调用次数推算网络请求量。

仅传 `keyword` 的旧调用继续有效，由上游默认读取第 1 页。无模型模式的 `/search 关键词` 仍为关键词查询快捷入口，不解析结构化筛选标志。URL、薪资多选及更多列表筛选是后续扩展范围。

## 求职者沟通列表

配置模型后，可要求“查看求职沟通的第 1 页”或明确查询下一页。模型工具 `boss_chat` 只接受可选正整数 `page`，默认 1；一次提交指定逻辑页，不补取消息、不回复、不导出，也不自动翻页。无模型模式尚无 `/chat` 快捷命令。

例如工具参数 `{"page":2}` 读取第 2 页；读取列表不改变角色、凭据或浏览器来源，当前业务上下文仍由用户配置决定，不能视为账号身份核验。列表标识、文本和上游建议命令不增加工具权限。

固定业务版本返回 `pagination=null`，表示后续页未知；空列表和条数不能证明查询结束。上游可能把缺失/null/真实零未读数都输出为 `unread=0`，把缺失最近消息输出为 `last_msg="-"`；这些值不能证明已读或没有消息。`initiated_by` 是关系发起方，非最近发言方；`msg_status` 也不是已核实的阅读状态，不能据此判断“待我回复”。工具保留来源值，不补造已丢失的事实。

请求、认证及本地状态维护沿用业务 CLI，无法保证单次网络访问或首次限制即停；收到最终受支持停止码后暂停当前回合，不执行同批后续工具或自动模型续跑。恢复会话只读取历史，不自动重查；处理限制后由用户明确发起后续任务。
